# Домен api.shlokahub.com в Amvera

Production API доступен через `https://api.shlokahub.com` в Amvera. Привязка домена
и проверка сайта приняты 2026-09-11. При обычном выпуске достаточно проверки из
раздела 4; шаги 1–3 нужны при настройке или восстановлении привязки домена.

## 1. Получить DNS-записи в Amvera

1. Открой приложение API → **Настройки → Доменные имена → Добавить доменное имя**.
2. Выбери **HTTPS** и собственный домен, введи `api.shlokahub.com` без `https://`.
3. Если форма запрашивает путь и порт, укажи `/` и `80`.
4. Скопируй показанные Amvera значения **A** и **TXT**, включая имя TXT-записи.
   Оставь форму открытой: подтверждать привязку нужно после настройки DNS.

Порядок привязки: [документация Amvera](https://docs.amvera.ru/applications/configuration/network.html).

## 2. Заменить записи в Cloudflare

Открой **shlokahub.com → DNS → Records**.

1. Сохрани у себя прежние значения записей для `api`.
2. Удали конфликтующий CNAME для `api`, если он есть. Замени старые A-записи
   для `api` на выданные Amvera; удали устаревшие AAAA для этого же имени.
3. В итоге должны быть следующие записи:

| Type | Name | Content | Proxy status | TTL |
| --- | --- | --- | --- | --- |
| A | `api` | Точный IP из Amvera | **DNS only**, серое облако | Auto |
| TXT | Точное имя из Amvera | Точное TXT-значение из Amvera | — | Auto |

Для TXT можно указать полное имя, показанное Amvera. Не подставляй `@`, если
Amvera просит другое имя. Остальные DNS-записи, включая `app`, оставь как есть.

Сохрани **DNS only** и после выпуска сертификата: для этого переключения запросы
должны идти напрямую в Amvera. [Что означает DNS only](https://developers.cloudflare.com/dns/proxy-status/).

## 3. Подтвердить домен и дождаться HTTPS

1. Вернись в форму Amvera и нажми **Подтвердить и привязать**.
2. Если записи ещё не найдены, подожди и повтори. По документации Amvera
   распространение DNS может занять до 24 часов.
3. Дождись выпуска сертификата для `api.shlokahub.com`.

Если привязка не проходит, сверь A и TXT с формой Amvera и проверь, что A-запись
имеет серое облако. [Проверка DNS и выпуск сертификата](https://docs.amvera.ru/applications/configuration/network.html).

## 4. Проверить API и сайт

В Терминале выполни:

```bash
curl --silent --show-error --max-time 30 --include https://api.shlokahub.com/health/live
curl --silent --show-error --max-time 30 --include https://api.shlokahub.com/health/ready
```

Оба ответа должны быть **HTTP 200** с `{"status":"ok"}`, без ошибок сертификата.
Не добавляй `-k`: проверка должна подтвердить рабочий HTTPS.

Затем:

1. Открой `https://app.shlokahub.com` в окне инкогнито.
2. До входа открой DevTools → **Network → Fetch/XHR** и включи **Preserve log**.
3. Войди существующей учётной записью и открой библиотеку или другую защищённую страницу.
4. В Network проверь успешный запрос входа
   `/api/auth/login` и запрос данных открытой страницы. Оба должны идти на
   `https://api.shlokahub.com`, а данные — отображаться на странице.
5. В Amvera проверь логи последней сборки и запуска: нет ошибок запуска и явной
   утечки секретов; после проверочных запросов нет новых ошибок приложения.

Frontend сохраняет прежний API origin; отдельный релиз для смены адреса не нужен.
Если любая проверка не прошла, выпуск ещё не подтверждён. Проверь DNS/TLS,
запуск API и доступ к Neon по [production runbook](amvera-production.md).

После проверки достаточно сообщить: «Оба health — 200, вход и защищённая страница
работают, логи без ошибок и видимых секретов». Пароли, токены, внутренние
идентификаторы, содержимое ответов с пользовательскими данными и полные логи
в отчёт не копируй.
