# Исключения из pen.dev UI-контракта

Канонический контракт: `design/pen-design.pen`. Реестр содержит только текущие
намеренные расхождения, явно принятые владельцем продукта. Нерешенные
`UI Contract Collision` хранятся в соответствующих specs/tickets.

## UIE-001 — Статусы и действия карточек библиотеки

- Причина: продуктовый контракт требует показывать личный статус шлоки и
  действия управления, включая `Учить`, `Убрать` и `Повторить`; базовая карточка
  фиксирует только переход к шлоке.
- Design reference: `Product / Shloka Card` (`Vzs9b`), `Библиотека — буду
  учить` (`g0MoYL`).
- Область реализации: `apps/web/src/shared/design-system/components/shloka-card.tsx`,
  `apps/web/src/features/library/ui/library-view.tsx`.
- Условие удаления: сохраненный дизайн получает варианты карточки со статусами и
  соответствующими action sets либо продуктовый контракт перестает их требовать.

## UIE-003 — Раскрытые списки дашборда

- Причина: `Показать еще N` и `Показать все` раскрывают полные списки на месте,
  продолжая существующие вертикальные patterns без отдельных design states.
- Design reference: `Дашборд - обычный` (`xJFoj`), `Product / Review Pack /
  Active` (`MTM4W`), `Product / Want To Learn Block` (`OPAt8`).
- Область реализации: `apps/web/src/features/dashboard/dashboard.page.tsx`.
- Условие удаления: сохраненный дизайн фиксирует оба раскрытых состояния либо
  продуктовый flow больше не раскрывает списки inline.

## UIE-004 — Функциональные действия потока повторения

- Причина: дизайн используется как ориентир для компоновки, а актуальные
  тексты и переходы изменены по решению владельца от 17.09.2026 без правок `.pen`.
  Для полного текста после подсказки и после неудачного вспоминания отдельных
  макетов нет; сохраняются действия «Завершить» и «Дальше».
  После самостоятельного вспоминания «Все правильно» и «Сделал ошибку»
  расположены сразу под полным текстом; отдельный шаг «Как получилось?»
  и действие «Оценить результат» удалены. На экране полного текста пояснение:
  «Оцените себя честно — алгоритм предложит чаще повторять трудные шлоки,
  чтобы быстрее их запомнить.»
  После сохранения результата показывается «Повторение завершено» с названием
  шлоки и подтверждением сохранения, только если в зафиксированной пачке есть
  следующая шлока. Если её нет, сразу открывается дашборд.
  После раскрытия текста с результатом `не смог вспомнить` действие «Дальше»
  открывает завершение или дашборд по тому же правилу, без повторной записи.
  Компоновка взята из завершения заучивания, тексты относятся к повторению.
  «Закончить» возвращает на дашборд; «Повторить следующую» появляется, если
  в зафиксированной пачке есть следующая шлока, и только это действие запускает
  её повторение. Действие «Выбрать другую» на завершении повторения отсутствует
  во всех случаях по дополнительному решению владельца.
  По дополнительному решению владельца сверху на всех состояниях повторения,
  включая загрузку, ошибку и завершение, добавлен существующий `PageHeader`
  со стрелкой «Назад». Он возвращает по истории приложения к странице входа;
  при прямом открытии без предыдущей страницы приложения — на дашборд.
  Возврат не записывает новый результат повторения.
- Design reference: `Повторение — текст скрыт` (`M6fBeF`), `Повторение — первая
  подсказка` (`Zt9yX`), `Повторение — вторая подсказка` (`dtDuy`), `Повторение —
  полный текст / без подсказки` (`s0VvGA`), удаляемый из кода `Повторение —
  результат` (`E41yd`); основа завершения — `Заучивание — завершение без
  следующей` (`ak4Su`) и `Заучивание — завершение` (`IQcqK`);
  паттерн возврата — `Product / Layout / Back Header` (`haku8`).
- Область реализации: `apps/web/src/features/review-shloka/review-shloka.page.tsx`.
- Условие удаления: сохраненный дизайн отражает оценку на полном тексте,
  завершение повторения с явным продолжением и пропуском при отсутствии
  следующей шлоки, верхнюю кнопку возврата
  и актуальные подписи всех действий.

## UIE-005 — Функциональный состав настроек

- Причина: текущий продукт не поддерживает выбор типа транслитерации, но должен
  показывать данные учетной записи и выход наряду с hard mode и переходом в
  админку.
- Design reference: `Настройки` (`HTlzD`).
- Область реализации: `apps/web/src/features/settings/settings.page.tsx`.
- Условие удаления: дизайн и продуктовый контракт синхронизируются по выбору
  транслитерации, данным учетной записи и выходу.

## UIE-006 — Обязательные поля admin-форм

- Причина: API/domain contract требует коды частей и глав, выбор части,
  неизменяемую ссылку на шлоку и предупреждение об изменении канонического
  текста; design components не фиксируют весь этот функциональный состав.
- Design reference: `Product / Source Admin Form` (`QUgwl`), `Product / Shloka
  Admin Form` (`gkqb9`).
- Область реализации: `apps/web/src/features/admin/source-editor/`,
  `apps/web/src/features/admin/shloka-editor/`.
- Условие удаления: сохраненные admin-form components отражают обязательные
  domain-поля и safety states либо соответствующие требования удалены из
  продукта.
