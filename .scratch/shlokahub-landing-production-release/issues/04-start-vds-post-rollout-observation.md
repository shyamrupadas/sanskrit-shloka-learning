# 04 — Передать общий VDS в post-rollout наблюдение

**What to build:** оператор получает безопасно зафиксированный эксплуатационный baseline общего VDS и ограниченный режим наблюдения: результаты четырёх первых deploy сведены вместе, дальнейшие проверки имеют расписание и владельца, а масштабирование допускается только по измеренным признакам нехватки ресурсов.

**Blocked by:** 03 — Провести и принять первый production rollout landing

**Status:** awaiting-human-review
Accepted: 2026-08-06

- [x] Вне repository зафиксированы необходимые для эксплуатации фактические targets и identifiers без private key, Secret values, access tokens, пользовательских данных и другого key material.
- [x] Для каждого из четырёх первых deploy сохранены timestamp и сопоставимые показатели диска, `MemAvailable`, swap, OOM, load, traffic и размеров журналов; отсутствующие измерения явно отмечены и восстановлены повторной безопасной проверкой, где это возможно.
- [x] Назначены владелец и проверяемое расписание: ежедневно в первую неделю после cutover, затем еженедельно и перед upgrade ОС или тарифа.
- [x] Еженедельная проверка дополнительно охватывает необходимость перезагрузки, размеры и последние ошибки Nginx, неуспешные systemd units и месячный трафик.
- [x] Дисковое предупреждение возникает при занятости root filesystem от 70% или свободном месте менее 2 ГБ; upgrade до 50 ГБ рассматривается после безопасной очистки при занятости от 80%, свободном месте менее 1,5 ГБ или риске оставить менее 2 ГБ после следующего deploy.
- [x] Предупреждение по памяти возникает, если `MemAvailable` ниже 200 MiB и swap выше 256 MiB в трёх последовательных проверках вне package upgrade; upgrade до 2 ГБ рассматривается при OOM, устойчивом swap выше 512 MiB либо постоянном swap I/O с заметной задержкой.
- [x] Устойчивый 15-minute load выше `0.7`, неожиданный рост диска более чем на 500 МБ за неделю и прогноз использования более 80–90% месячного трафика приводят к диагностике причины до масштабирования.
- [x] Если пороги не достигнуты, текущий VDS сохраняется без превентивного upgrade; если достигнуты, первым вариантом после отдельного подтверждения владельца остаётся upgrade существующего VDS до 2 ГБ RAM и 50 ГБ диска, а не создание второго VDS.
- [x] Для выполнения режима наблюдения не добавлены постоянный uptime monitoring, paging, APM или новая observability-платформа.
