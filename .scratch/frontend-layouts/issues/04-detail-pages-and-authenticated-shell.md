# 04 — Страница шлоки, серия дней и оболочка авторизованной зоны

**What to build:** Пользователь открывает страницу шлоки и серию дней без общего нижнего меню, с предусмотренной каждой страницей шапкой и доступным содержимым. После переноса всех страниц пользовательской авторизованной зоны выбор меню, высоты и отступов задают страницы, а проверка входа работает без визуальной оболочки маршрута.

**Blocked by:** 02 — Повторение; 03 — Разделы с нижним меню

**Status:** ready-for-agent

- [ ] Страница шлоки и серия дней во всех существующих состояниях используют общую композицию; длинное содержимое доступно, а отсутствующее меню не оставляет пустого места и само по себе не добавляет шапку.
- [ ] Страница определяет состав шапки и действие возврата; существующие переходы сохранены.
- [ ] Во всех маршрутах пользовательской авторизованной зоны состав областей задаётся явно страницей, а не условиями по адресу; проверки этих маршрутов и прокрутки проходят.
- [ ] Удалены визуальный `AuthenticatedLayout` и условия по `pathname`. Группа авторизованных маршрутов сохраняет проверку входа в `beforeLoad` и без собственного UI пропускает дочерние страницы; маршруты и переходы не меняются.
- [ ] Обновление серверной сессии, актуализация аккаунта и обработка `401` вынесены из `ProtectedLayout` в единый механизм сессии или маршрутизатора, который работает и для пользовательской зоны, и для админки. `ProtectedLayout` удалён; до тикета 06 админка сохраняет свою текущую визуальную композицию без повторного обновления сессии.

Проверить прямой вход, перезагрузку, выход и истёкшую сессию на защищённом маршруте. Решение о входе в админку не должно опираться только на сохранённую в браузере роль; серверная авторизация API остаётся обязательной.
