# 11 — Проверить визуальный прототип флоу заучивания

Type: prototype
Status: resolved
Blocked by: 10 — Собрать цельный текстовый UX-прототип; 13 — Определить способ и участников проверки прототипа

## Question

Как текстовый wireflow выглядит в mobile-first визуальном прототипе и какие изменения нужны после согласованной проверки его иерархии, читаемости, плотности, расположения помощи и приоритета действий?

## Prototype

- [Визуальный прототип флоу заучивания](../prototypes/visual-flow/README.md): три mobile-first композиции одного согласованного state machine, переключаемые через `?variant=A`, `?variant=B` и `?variant=C`.
- [Экспертная проверка](../prototypes/visual-flow/expert-review.md): проверенные состояния, исправленные дефекты и рекомендация варианта A для владельческой оценки.

## pen.dev references

- `Заучивание — шлока` (`QPXXW`), saved state inspected 2026-09-02: frame 390×844, крупные Noto Serif заголовок и текст, существующие primary/secondary button patterns; устаревшие `Повторить`/`Добавить` и bottom navigation не переносятся.
- `Заучивание — подтверждение` (`IQcqK`), saved state inspected 2026-09-02: frame 390×844, success icon и существующие button patterns; старые действия и bottom navigation не переносятся.
- Состояния `Помощника`, in-flow dialog совета, origin-aware выхода, status guard и неоднозначного сохранения в saved design отсутствуют. Прототип исследует их без изменения канонического `.pen`; перенос принятого результата выделен в отдельное последующее решение.

## Answer

Владелец выбрал вариант A — «Спокойный фокус» — как визуальное направление всего флоу. Базовая попытка сохраняет шлоку главным объектом: `Отмена` и `Совет` находятся в спокойном header, `Помощник` остаётся единственным вторичным действием после текста, а `Выучил` закреплён внизу как однозначное главное действие. Bottom navigation на сфокусированные экраны не переносится.

Тот же визуальный язык применяется к линейному `Помощнику`, modal bottom sheet совета, состояниям сохранения и ошибки, status guard и устойчивому success-state. Во время `Сохраняем…` все конфликтующие действия disabled. Dialog совета изолирует фон, удерживает клавиатурный фокус, закрывается по Escape и возвращает фокус к вызвавшему действию. Success-state оставляет `Закончить` главным действием, а продолжение требует отдельного выбора.

Варианты B — «Учебное поле» и C — «Текст прежде всего» отвергнуты как целостные направления: B создаёт лишнюю плотность и конкуренцию поддержки с текстом, C чрезмерно отделяет помощь и расходится с существующим button pattern. Они сохраняются только как исследовательский первоисточник сравнения и не должны неявно смешиваться с выбранным вариантом A.

Экспертная проверка выполнена через Chrome DevTools MCP в viewport 390×844. После исправлений Chrome MCP Lighthouse завершился без ошибок: Accessibility 100, Best Practices 100, SEO 100 и Agentic Browsing 100. Следующий шаг — перенести именно принятый вариант A и все согласованные состояния в канонический `design/pen-design.pen`, затем получить владельческую приёмку и сохранённые node IDs.
