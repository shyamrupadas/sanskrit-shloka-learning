# 02 — Расширить API серии льготным периодом и пятидневной историей

**What to build:** Расширить публичное представление серии дней так, чтобы клиент получал счетчик с трехдневным льготным периодом, состояние продолжения сегодня и фактическую историю последних пяти локальных дней. Результат должен быть полностью проверяем через защищенный API без нового хранилища или отдельного endpoint.

**Blocked by:** None — can start immediately

**Status:** awaiting-human-review
Accepted: 2026-08-22

- [ ] Серия считает уникальные локальные дни со значимой активностью, а несколько действий в один день увеличивают ее только один раз.
- [ ] Завершенное повторение и перевод шлоки в состояние «повторяю» остаются единственными источниками значимой активности.
- [ ] Промежутки между соседними днями активности до трех календарных дней включительно сохраняют одну серию; больший промежуток начинает новую серию.
- [ ] Значение серии сохраняется без увеличения в течение всего третьего пропущенного дня и становится `0` в начале четвертого.
- [ ] Первая значимая активность после завершения серии начинает новую серию со значения `1`, не восстанавливая прежний счетчик.
- [ ] Ответ существующего защищенного запроса содержит ровно пять календарных дней пользователя от самого раннего к сегодняшнему, включая дни без активности.
- [ ] Каждый элемент истории содержит локальную календарную дату и признак значимой активности; история не очищается при завершении серии.
- [ ] Расчет счетчика, состояния сегодня и истории использует переданную IANA-таймзону и корректен на границе UTC-дня.
- [ ] Публичная схема ответа и сгенерированные контрактные артефакты обновлены штатным генератором.
- [ ] Интеграционные тесты публичного handler с настоящим сервисом, управляемыми часами и fake-репозиториями покрывают нулевую серию, допустимые промежутки, четвертый пропущенный день, новую серию, смешанную пятидневную историю и границу таймзоны.
- [ ] Изменение не вводит новую таблицу, миграцию базы данных, агрегированное хранилище или отдельный endpoint.
