# 05 — Переключить api.shlokahub.com на Amvera

**What to build:** Перевести канонический API origin на уже проверенный deployment Amvera и подтвердить работу production frontend через HTTPS, сохраняя Railway до завершения проверки.

**Blocked by:** 04 — Развернуть и проверить API на бесплатном домене Amvera

**Status:** awaiting-human-review
Accepted: 2026-09-11

- [x] В Amvera добавлен custom domain `api.shlokahub.com`, а конфликтующие Railway DNS records заменены точными `A` и `TXT`, выданными Amvera.
- [x] DNS-настройки позволяют Amvera подтвердить владение доменом и выпустить TLS certificate без traffic splitting, canary или специального zero-downtime механизма.
- [x] После готовности TLS `/health/live` и `/health/ready` успешно отвечают через `https://api.shlokahub.com`.
- [x] Production frontend сохраняет прежний API origin и без отдельного frontend release позволяет войти существующей учётной записью и открыть одну защищённую страницу.
- [x] В build/runtime logs после cutover нет startup errors или явной утечки secrets; итоговый отчёт не содержит credentials, внутренних идентификаторов или пользовательских данных.
- [x] Railway service и его конфигурация остаются нетронутыми до принятия результатов канонического smoke-check. Принято с уточнением владельца: проект Railway уже удалён к моменту закрытия тикета; см. результаты ниже.

По решению пользователя настройки Amvera и Cloudflare и внешние проверки
выполняются вручную. [Пошаговая инструкция](../../../docs/operations/amvera-domain-cutover.md).

## Результаты и приёмка — 2026-09-11

Пользователь выполнил ручную настройку, сообщил «все работает» и явно попросил
закрыть задачу. Результаты переключения и проверок по инструкции приняты по
подтверждению пользователя. Агент отдельно подтвердил наличие ожидаемой TXT-записи
на авторитетном DNS-сервере Cloudflare и через Google DNS; health endpoints,
вход и логи в этой сессии агентом не проверялись.

В том же сообщении пользователь сообщил, что уже удалил проект Railway.
Точная последовательность удаления и smoke-check отдельно не проверялась;
владелец принял результат переключения с этим уточнением. Удаление устаревшей
Railway-конфигурации и обновление эксплуатационной документации остаются в тикете 06.
