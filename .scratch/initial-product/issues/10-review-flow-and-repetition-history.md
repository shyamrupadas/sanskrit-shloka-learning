# 10 — Поток повторения и история повторений

**What to build:** Сделать поток повторения из дашборда и из карточек `Повторяю` в библиотеке. Поток должен проводить пользователя через вспоминание, подсказки, раскрытие полного текста, выбор результата и создание записей истории повторений только для завершенных повторений; незавершенные попытки не должны иметь побочных эффектов.

**Blocked by:** None — can start immediately

**Status:** awaiting-human-review
Accepted: 2026-07-13

- [x] Пользователь может начать повторение со шлоки к повторению сегодня на дашборде или через `Повторить` на карточке `Повторяю`.
- [x] Первый экран просит пользователя произнести шлоку по памяти до раскрытия текста.
- [x] Последовательность подсказок фиксирована: первая половина первой строки, затем вся первая строка, затем весь текст.
- [x] Открытие полного текста после неудачного вспоминания записывает результат `не смог вспомнить`.
- [x] Если пользователь вспомнил самостоятельно, приложение показывает полный текст с действиями `Все правильно` и `Сделал ошибку` на том же экране.
- [x] `Все правильно` записывает `вспомнил без ошибки`; `Сделал ошибку` записывает `вспомнил с ошибкой`; завершение после подсказки записывает `вспомнил с подсказкой`.
- [x] Завершенная запись истории повторений включает пользователя, шлоку, время завершения, день пользователя и результат.
- [x] Выход из потока повторения до завершения не создает запись истории и не убирает шлоку из сегодняшних кандидатов.
- [x] На всех состояниях повторения слева сверху доступна стрелка `Назад` по существующему паттерну `PageHeader`: возврат по истории приложения, а при прямом входе без предыдущей страницы приложения — на дашборд. Кнопка не сохраняет новый результат.
- [x] После завершения одной шлоки экран `Повторение завершено` появляется, только если в зафиксированной пачке есть следующая шлока. `Закончить` возвращает на дашборд, `Повторить следующую` запускает следующую шлоку. Действия `Выбрать другую` нет. Если следующей шлоки нет, сразу открывается дашборд.
- [x] Тесты покрывают все четыре результата, вход с дашборда, вход из библиотеки, незавершенный выход без побочных эффектов, переход к следующей шлоке текущего потока и завершение дашборда после последнего кандидата.

## Поведение потока

- Поток использует действия `Вспомнил` / `Нужна подсказка`, затем
  `Вспомнил` / `Ещё подсказка` или `Показать весь текст`. После подсказки
  действие `Завершить` на полном тексте сохраняет результат `вспомнил с подсказкой`;
  после самостоятельного вспоминания на полном тексте доступны
  `Все правильно` / `Сделал ошибку`. Пояснение: «Оцените себя честно — алгоритм
  предложит чаще повторять трудные шлоки, чтобы быстрее их запомнить.»
  Оба пути после сохранения открывают завершение, если есть следующая шлока,
  иначе — дашборд. Для `не смог вспомнить` запись сохраняется при раскрытии
  текста, а `Завершить` выполняет тот же переход без повторного запроса.
- При входе фиксируется текущий авторитетный список кандидатов. После завершения
  следующая шлока из этого snapshot открывается только по `Повторить следующую`.
  `Закончить` доступно на экране завершения и возвращает на дашборд, который
  заново получает актуальное состояние. При исчерпании пачки переход на
  дашборд происходит автоматически, без экрана завершения повторения.

## Результат

- Добавлен защищенный `POST /api/library/items/{shlokaCode}/complete-review`.
  Бэкенд принимает один из четырех результатов и IANA-таймзону, проверяет
  статус `повторяю` и сохраняет пользователя, шлоку, серверное время
  завершения, день пользователя и результат в существующую таблицу
  `shloka_reviews`.
- Добавлен route `/library/shlokas/$shlokaCode/review` с последовательными
  экранами скрытого текста, двух подсказок, полного текста с оценкой результата
  и завершения. До завершения запрос записи не отправляется.
- Дашборд открывает поток по выбранной шлоке к повторению сегодня, а карточка
  `Повторяю` получила действие `Повторить`. После записи dashboard queries
  инвалидируются, поэтому завершенная шлока исчезает из кандидатов дня.
- API tests покрывают четыре результата, локальный день, обязательный статус
  и PostgreSQL-запись; contract test защищает публичную команду; web
  integration tests покрывают обе точки входа, подсказки, отсутствие побочных
  эффектов при выходе, переход по snapshot и завершение дашборда.
