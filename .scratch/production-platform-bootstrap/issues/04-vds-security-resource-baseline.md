# 04 — Закрепить security- и resource-baseline VDS

**What to build:** общий production-host устойчив к типовым SSH-атакам, неконтролируемому росту журналов и кратковременному дефициту памяти, сохраняя минимально необходимую сетевую поверхность и управляемые обновления.

**Blocked by:** 03 — Поднять изолированную HTTP-платформу для четырёх сайтов

**Status:** ready-for-human

Ручная инструкция: [`docs/operations/vds-security-resource-baseline.md`](../../../docs/operations/vds-security-resource-baseline.md)

- [ ] Firewall использует deny incoming / allow outgoing и публикует только TCP-порты `22`, `80` и `443`; фактически слушающие порты сверены с правилами.
- [ ] Fail2ban защищает SSH через firewall с согласованными ограничениями повторных попыток и подтверждённым active state.
- [ ] Journald ограничен 200 МБ и сохраняет 2 ГБ свободного места; штатная rotation журналов Nginx, firewall и Fail2ban проверена.
- [ ] Security updates устанавливаются ежедневно, автоматическая перезагрузка выключена, а наличие отложенной перезагрузки проверяется оператором.
- [ ] При отсутствии swap и наличии не менее 3 ГБ свободного места создан swap размером 1 ГБ; при нехватке места изменение остановлено до освобождения диска или повышения тарифа.
- [ ] Итоговая диагностика безопасно фиксирует диск, `MemAvailable`, swap, OOM, load, журналы и ownership без вывода чувствительных runtime-значений.
