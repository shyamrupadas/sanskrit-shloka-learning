# 02 — Обеспечить безопасный административный и automation-доступ к VDS

**What to build:** новый VDS имеет проверенный аварийно-восстанавливаемый контур доступа: оператор обслуживает сервер без прямого входа под root, а автоматические выпуски получают только минимально необходимый SSH-доступ.

**Blocked by:** 01 — Перевести production-контракт ShlokaHub с Netlify на канонический origin

**Status:** ready-for-agent

- [ ] До изменений проверены фактические Ubuntu release, свободные диск и память, активный swap и доступность recovery console.
- [ ] Административная учётная запись входит по SSH и получает `sudo`; это проверено в отдельной сессии до запрета root login.
- [ ] Automation-пользователь не имеет пароля и `sudo`, входит только по общему CI-ключу и не может использовать forwarding, tunnels или интерактивную аутентификацию.
- [ ] SSH-конфигурация прошла синтаксическую проверку; отдельно подтверждены доступ администратора, ограниченный доступ automation-пользователя и запрет прямого root login.
- [ ] SSH host key получен через доверенный bootstrap-канал, сверен по fingerprint и подготовлен для передачи в `SSH_KNOWN_HOSTS` без публикации в repository.
