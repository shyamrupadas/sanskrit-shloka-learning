# 01 — Origin-aware оболочка попытки

**What to build:** Пользователь открывает сфокусированную попытку из поддерживаемого контекста, видит актуальную шлоку к заучиванию и может безопасно вернуться именно в исходный контекст; прямая или устаревшая ссылка, ошибка загрузки и неактуальный статус не создают ложную активную попытку.

**Blocked by:** None — can start immediately

**Status:** awaiting-human-review
Accepted: 2026-09-04

- [x] Точки входа с дашборда и из каждой поддерживаемой вкладки библиотеки формируют типизированный `returnTo`, сохраняющий только разрешённый маршрут и допустимые query-параметры; внешние, auth/admin-, циклические и неизвестные маршруты отвергаются, а отсутствующее или неверное значение нормализуется в дашборд.
- [x] Маршрут перечитывает актуальную шлоку и показывает активную попытку только при статусе шлоки пользователя «буду учить»; статус «повторяю» получает отдельный guard, прочие неактуальные статусы безопасно выводят пользователя из попытки.
- [x] Loading-state позволяет отменить вход, load-error позволяет повторить GET или вернуться, а повторная загрузка после корректного ответа открывает активную попытку без дублирующих запросов и скрытых переходов.
- [x] Активная попытка показывает отображаемое название и полный канонический текст главным объектом, сохраняет прокрутку и достижимость действий для длинной шлоки и не разбирает `text` на пады.
- [x] Явные `Отмена` и возврат из guard используют replace-навигацию к проверенному `returnTo`, не меняют статус шлоки пользователя и не подменяют нативный browser/system Back.
- [x] App-level integration tests с настоящим router/query/session окружением проверяют round-trip всех поддерживаемых источников, fallback, loading/retry, status guard, отсутствие mutation-команд при выходе и ожидаемые URL/history.
- [x] Lint, web typecheck и целевые web unit/integration tests проходят.
