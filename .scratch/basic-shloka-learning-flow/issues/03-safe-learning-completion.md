# 03 — Безопасное завершение заучивания

**What to build:** Пользователь один раз подтверждает решение `Выучил`, видит честное состояние операции и может безопасно восстановиться после определённой или неоднозначной ошибки без неявного повторения команды перевода шлоки в повторение.

**Blocked by:** 01 — Origin-aware оболочка попытки

**Status:** ready-for-agent

- [ ] `Выучил` без дополнительного подтверждения отправляет одну существующую команду перехода `learning → reviewing` с IANA-таймзоной; pending-state показывает `Сохраняем…` и отключает `Отмена`, `Совет`, `Помощник` и повторный `Выучил`, не перехватывая системный Back.
- [ ] Подтверждённая ошибка, при которой переход гарантированно не состоялся, показывает понятное сообщение и разрешает только явное `Попробовать снова`; повторный POST невозможен до этого действия.
- [ ] Потеря соединения, timeout, нечитаемый ответ или иной неоднозначный исход после POST автоматически запускает только GET актуальной шлоки: `reviewing` ведёт к успеху, `learning` разрешает явный повтор, другой статус проходит через безопасный guard.
- [ ] Ошибка проверочного GET показывает `Результат пока неясен`; любое число действий `Проверить статус` выполняет только GET, а новый POST возможен лишь после подтверждения `learning` и явного `Попробовать снова`.
- [ ] App-level integration tests различают method и path, падают на неожиданный запрос и доказывают число и порядок POST/GET для pending, подтверждённой ошибки и всех исходов неоднозначного результата.
- [ ] Существующие backend-инварианты перехода, значимой активности, списка оставшихся шлок и идемпотентной повторной команды остаются зелёными; новые backend tests добавляются только при фактическом изменении этого поведения.
- [ ] Lint, web и API typecheck, целевые web integration tests и затронутые API tests проходят.
