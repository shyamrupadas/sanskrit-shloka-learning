# 05 — Унифицировать типографику админки

**What to build:** Перевести самостоятельные заголовки, описания, сообщения и санскритский текст каталога и форм админки на единый типографический контракт, чтобы управление общей библиотекой шлок использовало тот же визуальный язык, что и пользовательские разделы, без изменения административного поведения.

**Blocked by:** 02 — Перевести общие проектные компоненты на Typography

**Status:** ready-for-agent

- [ ] Заголовки, секционные названия, описания, статусы и сообщения админки используют `Typography` с сохранением существующей HTML-структуры через `as` там, где это нужно.
- [ ] Отображаемые названия и канонический санскритский текст в каталоге и формах используют `SanskritTypography` без отдельных размеров или весов.
- [ ] Form labels, inputs, textarea, select, buttons и tabs продолжают владеть собственной interactive typography.
- [ ] Веса 600/800 и локальные самостоятельные размеры заменены согласованными weights и variants без несвязанных визуальных изменений.
- [ ] Pencil admin screens и reusable admin forms синхронизированы с новой шкалой и основным foreground.
- [ ] Создание и редактирование источника шлоки и шлоки сохраняют существующие поля, валидацию, сообщения, действия и доступные имена.
- [ ] Admin route-level tests проверяют пользовательское поведение и семантические заголовки, не закрепляя приватную композицию Typography.
- [ ] Длинные названия источников и шлок сохраняют переносы, truncate и mobile layout.
- [ ] В admin feature не осталось прямых самостоятельных headings/paragraphs или ручной общей типографики вне разрешённых controls.
- [ ] Роли, маршруты, API-контракт, данные и backend не изменены; новые DB migrations не требуются.
- [ ] Обязательные frontend-проверки проходят.
