# 02 — Перевести общие проектные компоненты на Typography

**What to build:** Перевести самостоятельные заголовки и тексты общих проектных компонентов на новый типографический API, чтобы повторяемые UI-паттерны уже не собирали размер, line-height, weight и tone вручную. Пользователь должен видеть согласованную типографику во всех местах использования этих компонентов без изменения их поведения, доступных действий и layout.

**Blocked by:** 01 — Расширить pen.dev и frontend новым типографическим контрактом

**Status:** ready-for-agent

- [ ] Page header, empty state, карточка шлоки, строка настроек и accordion используют `Typography` или `SanskritTypography` для самостоятельного текста.
- [ ] Заголовочные уровни и доступные имена общих компонентов сохранены; динамический уровень empty-state heading реализован через согласованный `as`.
- [ ] Текст внутри кнопок, вкладок, полей, labels и нижней навигации остаётся ответственностью соответствующих interactive primitives.
- [ ] Layout-классы для переносов, truncate, ширины и позиционирования сохранены без ручного переопределения общей типографической шкалы.
- [ ] pen.dev reusable-компоненты отражают новые варианты и основной foreground без изменения состава controls или пользовательского поведения.
- [ ] Существующие потребители общих компонентов продолжают собираться без обязательной миграции feature-кода в этом ticket.
- [ ] Component tests проверяют семантические заголовки, описания и действия через роли и доступные имена, а не через приватную композицию.
- [ ] В shared project components не осталось прямых самостоятельных `h1–h3` и `p`, кроме реализации самих типографических компонентов и документированных исключений.
- [ ] Backend, API-контракт, данные и схема базы данных не изменены; новые DB migrations не требуются.
- [ ] Обязательные frontend-проверки проходят.
