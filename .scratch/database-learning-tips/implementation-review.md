# Реализация серверных советов — задача 02

Дата: 2026-09-19. База изменений: `5729b107e51ddce05fb0ffbd4903eb4a50fb2513`.

Советы выдаёт `GET /api/learning/tips`: авторизованный пользователь любой роли получает `{ items: [{ id, title, text }] }` на русском в общем порядке. TypeSpec и generated client/backend/OpenAPI обновлены генератором. Страница запрашивает данные при входе; диалог фиксирует первый успешный список на попытку. Статический массив удалён.

В history хранится идентификатор попытки, в sessionStorage этой вкладки — список и позиция. Отдельная запись позволяет сохранить первый ответ даже во время посещения помощника или страницы советов. Незавершённый запрос переиспользуется между экземплярами диалога. Завершение и отмена удаляют только соответствующую серию; поздний ответ не создаёт удалённую запись. Старый индекс перезапускает только серию. Серверного хранения или синхронизации устройств нет.

## Выпуск и миграция

**Необходимо применить `0011_learning_tips`** (`apps/api/src/database/migrations/0011-learning-tips.ts`). Она создаёт `learning_tips` и `learning_tip_translations`, ограничения целостности/длины и однократно переносит три исходных материала. Выполненные миграции учитывает существующий migration runner; последующие изменения/удаления не перезаписываются seed.

Порядок выпуска:

1. Применить миграцию в целевом окружении штатной командой API `db:migrate:production` после backend build.
2. Развернуть аддитивный backend. Старый клиент продолжает работать со статическим списком.
3. На фактически развёрнутом API проверить: без сессии 401; с обычной сессией GET `/api/learning/tips` возвращает 200 и три исходных материала с правильными id/порядком/текстами. Проверить логи отсутствия ошибок миграции.
4. Только после этого выпустить одним frontend-релизом оба потребителя, сохранение серии и переход старого формата; проверить библиотеку и заучивание.

В этой задаче deployment и применение миграции к внешней БД не выполнялись. Пункты ticket о фактическом выпуске остаются открытыми release gates; успешные локальные проверки не заменяют проверку развёрнутого API.
