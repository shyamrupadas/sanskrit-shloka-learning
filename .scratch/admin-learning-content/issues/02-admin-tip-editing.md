# 02 — Открывать админку и создавать и редактировать советы

**What to build:** Администратор через единый вход выбирает каталог или обучение, создаёт и редактирует русский совет на отдельной странице и сразу публикует полную версию, сохраняя ввод при ошибке.

**Blocked by:** 01 — Подготовить UI-контракт админки и управления советами

**Status:** awaiting-human-review

- [x] Перед началом проверена готовность предшествующего результата «Советы из БД»: приняты его implementation tickets и доступен совместимый API/модель. Эта внешняя зависимость не подменяется локальным номером blocker.
- [x] Один административный вход ведёт на главную с двумя работающими разделами; неадминистратор не видит вход и не получает доступ к защищённым маршрутам.
- [x] «Каталог шлок» сохраняет управление источниками и шлоками и существующие отдельные формы; изменены только согласованные навигация и название.
- [x] «Обучение» сразу показывает административный список с заголовками и кратким текстом в общем порядке; загрузка, ошибка с повтором и пустой список различаются.
- [x] Создание и редактирование открываются отдельно; форма работает только с русским заголовком и текстом, без выбора языка.
- [x] Оба поля обязательны после удаления крайних пробелов, максимум 120/2000 символов; счётчики и ошибки понятны в форме, сервер независимо проверяет ограничения. Переносы обычного текста сохраняются, Markdown/HTML не интерпретируются.
- [x] Создание совета с языковой версией атомарно и добавляет его в конец; изменение заголовка и текста публикуется вместе. Ошибка не оставляет частичного материала и не меняет прежнюю опубликованную версию.
- [x] Успешное сохранение возвращает в список и сообщает о публикации; результат доступен через общий API чтения. Ошибка сохраняет введённые значения и допускает повтор.
- [x] «Отмена» и уход из изменённой формы, включая browser Back, предупреждают о потере ввода. Отказ от ухода сохраняет форму; после успешного сохранения предупреждения нет.
- [x] Назад ведёт по вложенности к списку, главной админки и «Еще». Возврат оформлен ссылкой по образцу страницы шлоки; отдельного действия «В приложение» нет. Пользовательская нижняя навигация внутри админки скрыта.
- [x] Сервер разрешает мутации только администратору, с действующими ответами на отсутствие сессии и недостаток роли. Чтение обычным пользователем не ограничивается административной ролью.
- [x] TypeSpec и generated artifacts синхронизированы. Серверные проверки доступа/валидации/атомарности, UI формы и навигации, browser Back и регрессия каталога проходят.
- [ ] UI соответствует единому сохранённому контракту со стрелками порядка и удалением. Этот тикет подготавливает создание/редактирование; новую админку не выпускать до готовности операций тикета 03. Отдельного UI-варианта без сортировки нет.
- [ ] Перед включением frontend фактически развёрнут и проверен API создания/редактирования с общим чтением и авторизацией. Успешный CI не заменяет проверку доступности endpoint.
- [x] Подготовлены к общему выпуску через тикет 03 единый вход, главная, каталог, список и создание/редактирование. Проверены мобильный экран, возвраты, сохранность возможностей каталога и отсутствие административного доступа у обычного пользователя.
- [x] Отчёт содержит результаты обязательных проверок, browser smoke, pen.dev references, evidence приложения, автора visual review и фактически выпущенные версии. Если добавлены миграции, они применены до зависимого API и перечислены в отчёте.

## Проверки

Сквозной сценарий создания/изменения проверяется API-обработчиком с fake repository и последующим общим чтением; атомарность — узким repository/executor test. UI — RTL страницы/формы и router с mocked API; Playwright — native Back и административные переходы. Обновить contract checks, сохранить catalog regression guard, выполнить обязательные lint/typecheck/unit и targeted API/contract/browser проверки.

## Внешняя зависимость

До кодовой части/выпуска проверить [«Советы из БД»](../../database-learning-tips/spec.md) и принятие её implementation tickets. Локальный граф не умеет ссылаться на другой каталог; отсутствие внешнего номера в Blocked by не снимает это условие. Подготовка дизайна админки может идти независимо.

## Условие выпуска

Владелец исключил промежуточный список без сортировки: она должна работать с первого выпуска. Тикет 02 готовит создание/редактирование и навигацию, затем тикет 03 завершает порядок и удаление. Новая админка выпускается после готовности обоих тикетов и проверки всех API; сам по себе тикет 02 не включает её в пользовательский интерфейс. Финальная проверка и выпуск входят в тикет 03, отдельной задачи выпуска нет.
