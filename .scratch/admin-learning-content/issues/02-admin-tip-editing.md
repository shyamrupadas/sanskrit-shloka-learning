# 02 — Открывать админку и создавать и редактировать советы

**What to build:** Администратор через единый вход выбирает каталог или обучение, создаёт и редактирует русский совет на отдельной странице и сразу публикует полную версию, сохраняя ввод при ошибке.

**Blocked by:** 01 — Подготовить UI-контракт админки и управления советами

**Status:** ready-for-agent

- [ ] Перед началом проверена готовность предшествующего результата «Советы из БД»: приняты его implementation tickets и доступен совместимый API/модель. Эта внешняя зависимость не подменяется локальным номером blocker.
- [ ] Один административный вход ведёт на главную с двумя работающими разделами; неадминистратор не видит вход и не получает доступ к защищённым маршрутам.
- [ ] «Каталог шлок» сохраняет управление источниками и шлоками и существующие отдельные формы; изменены только согласованные навигация и название.
- [ ] «Обучение» сразу показывает административный список с заголовками и кратким текстом в общем порядке; загрузка, ошибка с повтором и пустой список различаются.
- [ ] Создание и редактирование открываются отдельно; форма работает только с русским заголовком и текстом, без выбора языка.
- [ ] Оба поля обязательны после удаления крайних пробелов, максимум 120/2000 символов; счётчики и ошибки понятны в форме, сервер независимо проверяет ограничения. Переносы обычного текста сохраняются, Markdown/HTML не интерпретируются.
- [ ] Создание совета с языковой версией атомарно и добавляет его в конец; изменение заголовка и текста публикуется вместе. Ошибка не оставляет частичного материала и не меняет прежнюю опубликованную версию.
- [ ] Успешное сохранение возвращает в список и сообщает о публикации; результат доступен через общий API чтения. Ошибка сохраняет введённые значения и допускает повтор.
- [ ] «Отмена» и уход из изменённой формы, включая browser Back, предупреждают о потере ввода. Отказ от ухода сохраняет форму; после успешного сохранения предупреждения нет.
- [ ] Назад ведёт по вложенности к списку, главной админки и «Еще»; «В приложение» ведёт в «Еще». Пользовательская нижняя навигация внутри админки скрыта.
- [ ] Сервер разрешает мутации только администратору, с действующими ответами на отсутствие сессии и недостаток роли. Чтение обычным пользователем не ограничивается административной ролью.
- [ ] TypeSpec и generated artifacts синхронизированы. Серверные проверки доступа/валидации/атомарности, UI формы и навигации, browser Back и регрессия каталога проходят.
- [ ] UI соответствует сохранённому контракту первого этапа. Порядок и удаление добавляются следующим тикетом; пока их кнопки не показаны.
- [ ] Перед включением frontend фактически развёрнут и проверен API создания/редактирования с общим чтением и авторизацией. Успешный CI не заменяет проверку доступности endpoint.
- [ ] Самостоятельно выпущены единый вход, главная, каталог, список и создание/редактирование. Проверены мобильный и широкий экран, возвраты, сохранность возможностей каталога и отсутствие административного доступа у обычного пользователя.
- [ ] Отчёт содержит результаты обязательных проверок, browser smoke, pen.dev references, evidence приложения, автора visual review и фактически выпущенные версии. Если добавлены миграции, они применены до зависимого API и перечислены в отчёте.

## Проверки

Сквозной сценарий создания/изменения проверяется API-обработчиком с fake repository и последующим общим чтением; атомарность — узким repository/executor test. UI — RTL страницы/формы и router с mocked API; Playwright — native Back и административные переходы. Обновить contract checks, сохранить catalog regression guard, выполнить обязательные lint/typecheck/unit и targeted API/contract/browser проверки.

## Внешняя зависимость

До кодовой части/выпуска проверить [«Советы из БД»](../../database-learning-tips/spec.md) и принятие её implementation tickets. Локальный граф не умеет ссылаться на другой каталог; отсутствие внешнего номера в Blocked by не снимает это условие. Подготовка дизайна админки может идти независимо.

## Условие выпуска

Самостоятельный первый выпуск админки: после готовности API и UI-контракта публикуются вход, главная, каталог и создание/редактирование советов. Порядок и удаление поставляются следующим тикетом. Проверки и выпуск входят в этот функциональный тикет, отдельной задачи общего выпуска нет.

Поэтапная поставка утверждена владельцем 2026-09-19; соответствующее условие синхронизировано со спецификацией и решением о поставке.

## UI Contract Collision

- Требование: Единый вход, главная, каталог, список, создание/редактирование и защита несохранённых изменений.
- pen.dev reference: актуальные references для полного объёма ещё не подготовлены; исторические сведения из карты не являются новой проверкой. В рамках декомпозиции .pen не читался и не менялся.
- Расхождение: согласованный UX пока не подтверждён полным актуальным сохранённым UI-контрактом для этой задачи.
- Варианты решения:
  1. Обновить дизайн и получить human save с последующей проверкой сохранённых узлов.
  2. Изменить требование отдельным решением владельца.
  3. Разрешить design exception отдельным явным решением владельца с записью в реестр.
- Рекомендация агента: выбран вариант 1. До frontend code phase закрыть коллизию, получить актуальные pen.dev references и перечитать соответствующие сохранённые узлы. Наличие blocker на дизайн не заменяет inspection. Выполнять pen-ui-contract; исключений пока нет.
