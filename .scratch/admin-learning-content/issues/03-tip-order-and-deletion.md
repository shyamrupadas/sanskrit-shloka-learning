# 03 — Менять порядок и удалять советы

**What to build:** Администратор меняет порядок советов и окончательно удаляет выбранный материал с подтверждением, включая последний совет; успешные операции видны новым пользовательским чтениям, а ошибки сохраняют прежние данные.

**Blocked by:** 02 — Открывать админку и создавать и редактировать советы

**Status:** ready-for-agent

- [ ] Каждый совет можно переместить на одну позицию выше или ниже; невозможное направление у края недоступно.
- [ ] Перестановка сохраняется немедленно без отдельной публикации и меняет общий порядок, возвращаемый API чтения.
- [ ] Новый совет по-прежнему добавляется в конец; идентификаторы и тексты при перестановке не меняются.
- [ ] Неуспешная операция показывает ошибку и сохраняет прежние опубликованные данные и подтверждённый список.
- [ ] Подтверждение удаления называет совет и объясняет, что восстановление невозможно; отмена не меняет данные.
- [ ] Успешное удаление убирает совет и его языковые версии без осиротевших данных; последующее общее чтение его не возвращает. Порядок оставшихся советов сохраняется.
- [ ] Последний совет можно удалить; администратор видит предложение добавить первый совет, пользовательский API возвращает успешный пустой список.
- [ ] Ошибка удаления отображается отдельно и оставляет прежний опубликованный материал и подтверждённый список.
- [ ] Обе команды защищены административной ролью и описаны в TypeSpec; generated artifacts согласованы с реализацией.
- [ ] Начатая пользовательская серия остаётся неизменной по правилам первой спецификации; фоновая синхронизация не добавляется.
- [ ] Архив, скрытие и восстановление не добавлены; повторное развёртывание не возвращает удалённые начальные материалы.
- [ ] API/contract проверки защищают порядок, удаление и доступ; UI-проверки — направления, подтверждение/отмену, ошибки и последний совет. Серверный сбой не оставляет частичной перестановки или удаления.
- [ ] До включения controls фактически развернут и проверен API обеих операций; при необходимости миграции применены до зависимого API и перечислены в отчёте.
- [ ] Самостоятельно выпущено дополнение к работающей админке с порядком и удалением. Проверены общий пользовательский API и сохранность текущей попытки заучивания.
- [ ] Пройдены обязательные проверки и актуальный browser smoke админки; visual review выполнен на мобильной и широкой ширине по сохранённому контракту. Отчёт содержит версии, pen.dev references, evidence приложения и автора review.

## Проверки

Основные проверки через API-команды и последующее чтение; fake executor для границ атомарной перестановки и связного удаления. RTL списка с точными API mocks для краёв, подтверждения/отмены, ошибок и последнего совета. Переиспользовать тесты первой спецификации для неизменности серии, не дублировать их в новом browser suite. Выполнить targeted API/contract/UI проверки, обязательные lint/typecheck/unit и административный browser smoke; повторять не затронутые проверки только при изменениях или новых рисках.

## Условие выпуска

Самостоятельный следующий выпуск поверх уже работающей админки: сначала развернуть и проверить API порядка и удаления, затем включить соответствующие UI-действия. Проверки и выпуск входят в этот тикет. Общий merge backend и frontend не гарантирует доступность API до клиента.

## UI Contract Collision

- Требование: Стрелки изменения порядка, их недоступные состояния, подтверждение необратимого удаления, ошибки обеих операций и пустой список.
- pen.dev reference: актуальные references для полного объёма ещё не подготовлены; исторические сведения из карты не являются новой проверкой. В рамках декомпозиции .pen не читался и не менялся.
- Расхождение: согласованный UX пока не подтверждён полным актуальным сохранённым UI-контрактом для этой задачи.
- Варианты решения:
  1. Обновить дизайн и получить human save с последующей проверкой сохранённых узлов.
  2. Изменить требование отдельным решением владельца.
  3. Разрешить design exception отдельным явным решением владельца с записью в реестр.
- Рекомендация агента: выбран вариант 1. До frontend code phase закрыть коллизию, получить актуальные pen.dev references и перечитать соответствующие сохранённые узлы. Наличие blocker на дизайн не заменяет inspection. Выполнять pen-ui-contract; исключений пока нет.
