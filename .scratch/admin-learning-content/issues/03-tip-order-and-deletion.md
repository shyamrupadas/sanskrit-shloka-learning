# 03 — Менять порядок и удалять советы

**What to build:** Администратор меняет порядок советов и окончательно удаляет выбранный материал с подтверждением, включая последний совет; успешные операции видны новым пользовательским чтениям, а ошибки сохраняют прежние данные.

**Blocked by:** 02 — Открывать админку и создавать и редактировать советы

**Status:** awaiting-human-review

- [x] Каждый совет можно переместить на одну позицию выше или ниже; невозможное направление у края недоступно.
- [x] Перестановка сохраняется немедленно без отдельной публикации и меняет общий порядок, возвращаемый API чтения.
- [x] Новый совет по-прежнему добавляется в конец; идентификаторы и тексты при перестановке не меняются.
- [x] Неуспешная операция показывает ошибку и сохраняет прежние опубликованные данные и подтверждённый список.
- [x] Подтверждение удаления называет совет и объясняет, что восстановление невозможно; отмена не меняет данные.
- [x] Успешное удаление убирает совет и его языковые версии без осиротевших данных; последующее общее чтение его не возвращает. Порядок оставшихся советов сохраняется.
- [x] Последний совет можно удалить; администратор видит предложение добавить первый совет, пользовательский API возвращает успешный пустой список.
- [x] Ошибка удаления отображается отдельно и оставляет прежний опубликованный материал и подтверждённый список.
- [x] Обе команды защищены административной ролью и описаны в TypeSpec; generated artifacts согласованы с реализацией.
- [x] Начатая пользовательская серия остаётся неизменной по правилам первой спецификации; фоновая синхронизация не добавляется.

## Проверки

Основные проверки через API-команды и последующее чтение; fake executor для границ атомарной перестановки и связного удаления. RTL списка с точными API mocks для краёв, подтверждения/отмены, ошибок и последнего совета. Переиспользовать тесты первой спецификации для неизменности серии, не дублировать их в новом browser suite. Выполнить targeted API/contract/UI проверки, обязательные lint/typecheck/unit и административный browser smoke; повторять не затронутые проверки только при изменениях или новых рисках.

## Условие выпуска

Первый выпуск новой админки объединяет подготовленный результат тикета 02 с рабочими порядком и удалением. Сначала развернуть и проверить API всех операций, затем включить новую админку. Владелец исключил промежуточный выпуск без сортировки. Уточнение владельца от 2026-09-19: production-выпуск и production smoke выполняются владельцем отдельно и не блокируют закрытие реализации. Локальные итоговые проверки входят в этот тикет. Общий merge backend и frontend не гарантирует доступность API до клиента.
