# Прототип навигации админки и управления советами

Одноразовый интерактивный HTML-прототип для решения «Навигация админки и прототип управления советами». Проверяет структуру экранов и переходы на мобильном и широком экране. Не является продуктовым кодом или принятым визуальным контрактом.

## Открыть

Можно открыть `index.html` напрямую. Для просмотра через локальный сервер из корня репозитория:

```sh
python3 -m http.server 8768 --bind 127.0.0.1 --directory .scratch/admin-learning-content/prototypes/admin-navigation
```

- [A — Отдельные страницы](http://127.0.0.1:8768/?variant=A#admin).
- [B — Постоянное меню](http://127.0.0.1:8768/?variant=B#admin).
- [C — Список и редактор](http://127.0.0.1:8768/?variant=C#admin).

Варианты переключаются нижней панелью или клавишами ←/→ вне полей ввода. Параметр `variant` сохраняется в URL. Для входа через «Еще» используйте `#more` или кнопку «В приложение».

## Что сравнивается

| Вариант | Устройство | Компромисс |
| --- | --- | --- |
| A | Главная админки с двумя разделами, затем отдельные страницы списка и формы | Компактно на телефоне; для смены раздела нужен возврат на главную админки |
| B | Главная админки, постоянные вкладки разделов, отдельная форма | Быстрая смена раздела; меню занимает место и в редакторе |
| C | Главная админки, меню слева и список рядом с редактором на широком экране | Удобнее серия правок; сложнее компоновка. На телефоне список и форма открываются последовательно |

Владелец выбрал **A — Отдельные страницы**. Итоговое UX-решение находится в [«Навигации админки и прототипе управления советами»](../../decisions/03-admin-prototype.md#answer). Варианты B и C сохранены для контекста сравнения.

## Общие предложения для всех вариантов

- В «Еще» один вход «Админка», затем выбор «Каталога шлок» или «Обучения».
- «Обучение» сразу показывает блок «Советы», без отдельной страницы с единственным пунктом. Курсы и несуществующие разделы не показаны даже как заглушки.
- В админке нет нижней навигации пользовательского приложения. «В приложение» возвращает в «Еще»; возврат из формы ведёт к советам, из раздела — к выбору разделов.
- У формы есть явные «Сохранить» и «Отмена». Успех возвращает к списку и сообщает о публикации; ошибка оставляет введённые значения в форме.
- Уход из изменённой формы, в том числе через browser Back, требует подтверждения потери изменений. «Отмена» в подтверждении сохраняет форму.
- Список содержит заголовок, краткий текст и действия. Стрелки меняют порядок сразу; крайнее недоступное направление отключено. У C список компактный, удаление находится в редакторе.
- Удаление требует подтверждения с названием совета. Последний совет можно удалить; пустое состояние предлагает добавить первый.

Общие предложения вошли в выбранный вариант A; особенности B и C не выбраны. Правила данных из закрытых решений соблюдены: обычный текст, лимиты 120/2000, обязательные поля, добавление в конец и немедленная публикация. Каноническое место принятого решения — ticket по ссылке выше.

## Сценарии для просмотра

В верхней тёмной панели «ПРОТОТИП» находятся инструменты проверки, не входящие в предлагаемый UI приложения:

- Обычный список, пустой список, загрузка и ошибка загрузки. Переключение сценария восстанавливает исходные примеры или очищает список.
- «Ошибка следующего изменения» — одна ошибка сохранения, перестановки или удаления. Данные при ней не меняются; затем операцию можно повторить.
- «Сбросить пример» и «Начать из „Еще“».
- Состояние экрана, идентификаторы и порядок советов, признак несохранённых изменений и текущие поля формы.

## Ограничения прототипа

- Данные живут только в памяти вкладки. Реальные API, БД, авторизация и настройки пользователя не затрагиваются. Reload восстанавливает примеры.
- Размещение в `.scratch/.../prototypes/` следует локальному planning workflow: новый поток админки исследуется отдельно от действующего `/admin`, который сейчас является каталогом. Изменения продуктовых маршрутов не нужны для сравнения.
- Каталог представлен контекстным макетом существующих действий и иерархии. Его формы не переписаны; кнопки обозначают их место в потоке.
- Примеры основаны на трёх текущих советах; заголовки сделаны различимыми для оценки навигации. Это не решение о замене контента при миграции.
- Использована палитра и основные размеры сохранённого `.pen`; шрифт Inter имеет системный fallback. Прототип не подтверждает визуальное соответствие будущей реализации.
- Канонический `.pen` не менялся. Прототип не коммитился и не переносился в отдельную ветку: действующий запрет пользователя на изменение git index и коммиты имеет приоритет над общим workflow skill `prototype`.

## Проверка в браузере

Проверено через Playwright на 390×844 и 1280×900; список B дополнительно проверен на 320×700:

- Создание с двумя абзацами, публикация, перемещение и удаление.
- Обязательные поля, заголовок в 120 и текст в 2000 символов; отсутствие горизонтального overflow.
- Ошибка сохранения сохраняет введённый текст; повторное сохранение проходит.
- Подтверждение ухода, отмена browser Back с сохранением правки, подтверждённый уход без сохранения.
- Ошибка загрузки и повтор, пустой список и удаление последнего совета.
- Состояние загрузки; ошибки перестановки и удаления сохраняют прежние данные.
- У C список и редактор видны вместе на широком экране; на мобильном при редактировании видна только форма.
