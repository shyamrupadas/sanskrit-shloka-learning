# Одна админка без переключателя выпуска

Type: grilling
Status: resolved
Blocked by: 05 — Границы спецификаций и порядок перехода на новую админку

## Question

Устранить смешение темы флагов с порядком выпуска админки и определить исправление ошибочного ветвления интерфейса.

## Answer

Владелец уточнил 2026-09-19: «флаги вообще пока не трогай. Пусть будет так, как было до этой карты», «потом с ними разберемся». Это заменяет промежуточное обсуждение назначения и устройства флагов.

- Существующие флаги, настройки пользователя и алгоритм повторения остаются как до этой карты. Их проектирование и изменение отложены; новая конфигурация, API или UI управления флагами не добавляются.
- Дорабатывается единственная админка. Сохраняется выбранная в решении 03 структура «Еще → Админка → Каталог шлок / Обучение», переиспользуются существующие каталог и формы. Старый и новый режимы одной админки не нужны.
- Добавленный при реализации карты `VITE_ADMIN_LEARNING_ENABLED`, его проверки и передача через GitHub Variables удаляются. Замена другим флагом или константой `true` не требуется. В обычном локальном запуске административная роль дает доступ ко всему согласованному административному интерфейсу.
- Авторизация остается прежней: административные маршруты и команды доступны только администратору. Наличие разделов не зависит от параметров выпуска.
- Рабочая сортировка и удаление доступны вместе с созданием и редактированием; частичный вариант списка не выпускается.
- Production-выпуск и проверку развернутых API владелец выполняет отдельно. Готовность реализации не означает выполненный deployment. Порядок backend → frontend относится к организации выпуска владельцем и не требует продуктового флага.

## Причина исправления

Решение 05 определяло последовательность поставки, но не требовало системы флагов. В реализации 02 агент добавил переменную сборки и два режима интерфейса, а в 03 — зависимость от GitHub Repository Variable. Эти дополнения не соответствуют уточненному scope и удаляются. Каталог не дублировался: ветвление находилось внутри существующей административной фичи.

Обнаруженное при обсуждении расхождение между общим флагом повторения в коде и намерением владельца относительно будущих личных настроек оставлено для отдельной работы. Документы исходного алгоритма, его код и настройки здесь не меняются.

ADR не нужен: исправление убирает несогласованное усложнение. Результаты проверки исправления фиксируются в `implementation-03.md`.
