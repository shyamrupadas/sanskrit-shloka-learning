# Локализация советов и серверная выдача содержимого

Type: grilling
Status: resolved
Blocked by: None - can start immediately

## Question

Как устроить хранение совета и его заголовка и текста в БД, чтобы сейчас сервер сохранял и выдавал только `ru`, а позднее можно было добавить английскую языковую версию того же совета? Согласовать языконезависимую идентичность совета, представление локали в данных и целостность русской версии при создании и редактировании.

Уточнение владельца: локаль в приложение сейчас не добавляется. Сервер использует `ru` по умолчанию, редактор работает только с русским текстом. Локаль пользователя, параметры выбора языка в API, fallback и UI переводов находятся за пределами текущей карты. Их не нужно проектировать, чтобы закрыть это решение.

Основание: владелец требует серверную выдачу текстов из БД и подготовку структуры к будущему i18n; `docs/adr/0001-i18n-and-transliteration-preferences.md` предусматривает будущий серверный выбор локализуемых текстов.

## Answer

Владелец подтвердил разделение совета и его языковых версий, обязательность заголовка и текста и их совместную публикацию после успешного сохранения.

- Хранить совет отдельно от его языковых версий: `tips` со стабильным `id` и `tip_translations` с `tip_id`, `locale`, `title`, `text`. Для пары `(tip_id, locale)` действует уникальность; перевод связан с существующим советом.
- Сейчас создание и редактирование всегда сохраняют русскую версию (`ru`). Пользовательский API всегда читает её из БД и возвращает `id`, `title`, `text`. Клиент не передаёт локаль, сервер не определяет её по браузеру или учётной записи.
- Заголовок и текст обязательны: после удаления пробелов по краям оба должны быть непустыми. Точные ограничения длины и формат текста относятся к решению «Правила редактирования, порядка и удаления советов».
- Создание совета и его русской версии выполняется атомарно. При редактировании заголовок и текст сохраняются вместе: ошибка не должна публиковать половину правки. Успешное сохранение сразу публикует полную русскую версию.
- Если создание завершается ошибкой, новый совет не появляется; если редактирование завершается ошибкой, сохраняется прежняя версия.
- Будущий английский перевод — дополнительная запись для того же `tip_id`; название и текст не являются идентификатором совета. Названия таблиц предварительные, окончательные имена определит спецификация.
- Прямые поля `title_ru`/`title_en` или отдельные независимые советы для каждого языка не использовать: каждый следующий язык не должен требовать новых колонок или дублирования сущности совета.
- Механизм выбора языка, fallback и редактор переводов остаются за пределами текущей работы. Наличие места для локали в хранилище не добавляет локаль в приложение.
