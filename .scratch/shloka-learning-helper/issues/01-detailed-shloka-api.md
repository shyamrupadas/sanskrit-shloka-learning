# 01 — Детальное API-представление шлоки с падами

**What to build:** Клиент получает для одной шлоки отдельное детальное представление с четырьмя каноническими падами и согласованным полным текстом, а повреждённые структурные данные отвергаются на серверной границе явной безопасной ошибкой вместо эвристического исправления на frontend.

**Blocked by:** None — can start immediately

**Status:** awaiting-human-review
Accepted: 2026-09-04

- [ ] TypeSpec определяет отдельный `LibraryShlokaDetailsDto`, сохраняющий поля компактного представления и добавляющий обязательный массив `padas` минимум и максимум из четырёх непустых строк; детальный GET возвращает этот DTO.
- [ ] Компактный `LibraryShlokaDto` остаётся контрактом списков, изменения статуса и завершения заучивания и не получает `padas`; generated OpenAPI, frontend client и backend handler types обновлены только генерацией из TypeSpec.
- [ ] HTTP/backend boundary во время выполнения проверяет количество, непустое содержимое и порядок пад, а также равенство `text === padas.join("\n")`; frontend не разбирает `text` и не восстанавливает пады.
- [ ] Нарушение инварианта возвращает документированный `500` с `ApiError.code = "DATA_INTEGRITY_ERROR"` и безопасным сообщением без внутренних значений и деталей хранения; существующая семантика `401` и `404` сохраняется.
- [ ] Contract tests защищают детальный DTO, ограничения четырёх пад, документированный `500` и отсутствие пад в компактных list/update/complete responses.
- [ ] Backend handler/service tests с fake repositories покрывают успешный порядок и согласованность проекций, отсутствие, пустую и лишнюю паду, несовпадение полного текста, безопасную ошибку и неизменные `401`/`404`.
- [ ] Генерация и тесты API-контракта, API typecheck и целевые API tests проходят без новой DB migration.
